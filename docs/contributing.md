# Contributing

Issues and PRs are welcome at
[github.com/sxa-lab/openhanji](https://github.com/sxa-lab/openhanji).

## Development setup

```bash
git clone https://github.com/sxa-lab/openhanji.git
cd openhanji
pip install -e ".[dev]"
```

## Tests

```bash
pytest                                              # full suite
pytest tests/unit/test_api.py::test_to_markdown_headings   # single test
pytest --cov=openhanji --cov-report=term-missing    # with coverage
```

The test suite is split into:

- **`tests/unit/`** — exercises the in-memory document model and
  converters. No HWPX parser, no test documents.
- **`tests/integration/`** — runs `HwpxParser` and the CLI against
  real HWPX test files in `tests/test_files/hwpx/`.

Any parser change must keep the integration tests passing. Files
that surface new bugs become regression test files.

## Lint, format, type-check

```bash
ruff check src/
ruff format src/
mypy src/openhanji/    # strict mode
```

`mypy --strict` is enforced. Every public symbol carries type hints,
and the docs autodoc relies on them.

## Documentation

The docs use **MkDocs + Material** with **mkdocstrings** for
autogenerated API references. To preview locally:

```bash
pip install -r docs/requirements.txt
mkdocs serve
```

Read the Docs builds from `.readthedocs.yaml` on every push to `main`
and on every PR (preview builds).

### Editing the API reference

The API pages under `docs/api/` mix two layers:

1. **Auto-generated** — `:::` directives (e.g. `::: openhanji.document.Run`)
   render the signature, fields, and types directly from the source.
   These stay in sync with the code automatically.
2. **Hand-written prose** — everything around the directives.
   Behavioral notes, gotchas, examples, and design rationale live in
   the `.md` file, **not** in source docstrings. Keep source
   docstrings short; put the depth here.

When a public symbol is renamed or a field is added, the autodoc
section updates without any docs edit. The surrounding prose may need
a follow-up.

## Adding a new output format

Four touch points, in order:

1. Add a `Document.to_<format>()` method in
   [`document.py`](api/document.md) (or a standalone
   converter function in `openhanji/converters/`).
2. Add the format name to the `--format` `click.Choice` in
   [`cli.py`](cli.md) `extract`.
3. Add the format → extension mapping to `_EXT_MAP` in `cli.py`
   (used for output filenames in directory mode).
4. Add a branch to `_render` in `cli.py`.

## Behavioral rule for the parser

**Never crash on unknown content** in the default (non-strict) mode.
Unknown XML must be skipped and logged at `WARNING`. Use the
`strict=True` path to escalate to
[`UnknownRecordError`](api/exceptions.md#unknownrecorderror) /
[`CorruptedFileError`](api/exceptions.md#corruptedfileerror).

PRs that crash the default path on previously-handled inputs will be
rejected.
